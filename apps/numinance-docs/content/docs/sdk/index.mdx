## What an SDK is and is not

The contract is the set of `.proto` files under `proto/numinance/` plus the JSON Schemas generated from the configuration kinds. An SDK in this repository is one of three things:

1. **Generated stubs.** Messages and service clients produced from the `.proto` files by a pinned generator. Python and TypeScript are only this.
2. **Handwritten helpers.** Code that applies rules a Protobuf schema cannot express: stream-shape checks, a strict YAML loader, an offline evidence verifier. Only Go has these.
3. **Command logic.** The Go package behind the `numi` command line, which the private engine build also runs.

None of the SDKs is the Numinance engine. Importing one does not give you an autonomous engineer, and it cannot widen a grant, approve a change or bypass policy. Authority stays with the runtime and your policy.

## Choosing a path

| You want to | Use |
| --- | --- |
| Load and validate kind YAML in a Go program | `sdk/go/kindyaml` (see [Go SDK](/docs/sdk/go)) |
| Verify an evidence export offline from code | `sdk/go/evidenceverify` or `numi evidence verify` ([CLI](/docs/cli/evidence-verify)) |
| Write a provider plugin | Go, against `sdk/go/plugin` and the generated stubs ([Custom plugin in Go](/docs/integrations/custom-plugin-go)) |
| Read or write Numinance messages from Python or TypeScript | Generated stubs, built from source ([Python](/docs/sdk/python), [TypeScript](/docs/sdk/typescript)) |
| Work in Rust, Java or any other language | Generate Protobuf clients yourself ([Generating clients](/docs/sdk/generating-clients)) |

<Callout type="warn" title="No tagged release yet">
  The repository declares Go 1.27 and the module is not tagged. Treat every SDK surface as pre-alpha: it can change before a tag, and the versioning policy for untagged packages is in the [versioning page](/docs/project/versioning).
</Callout>
