# schemas

JSON Schema 2020-12 for the configuration kinds in `numinance.kinds.v1`, and example documents.

- `gen/`: generated by `just gen` from `proto/numinance/kinds/v1`; never edit by hand. The schema of a kind is `gen/numinance.kinds.v1.<Kind>.jsonschema.strict.bundle.json`. Each file is self-contained: the messages it uses sit under `$defs` and every `$ref` is `#/$defs/...`. The generator also writes a file for every other message it sees (specs, `Metadata`, the annotation options); a loader does not use those.
- `examples/<Kind>/<name>.yaml`: at least one example per kind.
- Produced kinds: ContextBundle is built by Numinance, never authored. Its envelope is `apiVersion`, `kind` and `spec` (no `metadata`, no `extensions`); the loader refuses it, and its example is validated against its schema and protojson directly.
- Alpha kinds: EvalSet is at `apiVersion: numinance.dev/v1alpha1` (off by default). Its example is loaded only by a loader built with `WithAlphaKinds`, which the example test and `numi validate --files` use; the default loader refuses it.
- Keys: `apiVersion`, then proto snake_case for every other field (multi-word fields set `json_name`). Enum values use the full proto name (`SCOPE_ORG`); durations use the protobuf JSON form (`7200s`); `format: duration` in a schema is an annotation, not ISO 8601. The spelling is pending ratification and may change before the first tag.
- The schema is the first gate. The loader, `sdk/go/kindyaml`, is the second and also checks what the schema cannot: metadata and spec present, apiVersion and kind constants, no zero enum value, required lists non-empty, reverse-DNS `extensions` keys. `embed.go` embeds the kind schemas for it.
- Merge directives: a kind field declares how profile resolution merges it with the `(numinance.kinds.v1.merge)` field option; the JSON Schema does not carry it.
- `go test ./schemas` (from `numinance-spec/`) checks that every schema is 2020-12 and self-contained, pins the set of generated files and each kind's required keys, that every kind has the envelope fields, a schema and an example, that every example of a loaded kind decodes through the loader (schema and loader checks), names its directory's kind and survives `Encode` and `Decode`, that every example of a produced kind passes its schema and protojson and is refused by the loader, that kind fields keep snake_case JSON names, and where merge directives are declared.
