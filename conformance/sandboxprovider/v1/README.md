# sandboxprovider conformance kit, v1

Skeleton. The acceptance tests for a provider of `numinance.ports.sandboxprovider.v1.SandboxProviderService` (`proto/numinance/ports/sandboxprovider/v1/sandboxprovider.proto`). The kit version tracks the port minor; this skeleton tracks 1.0.0. The runnable kit (replay fixtures, live kit, harness) is added by the plugin host work package; until then this file is the list of cases the kit must hold. Modes are those of ADR 0015 that apply to a deployment-bound provider: replay and live publisher-run in an attested runner; a registry-installed sandboxprovider is refused (HOST-001), so registry-run does not apply. Column "Mode": `all` runs in every mode; `live` needs a real host, image and egress proxy and runs in the two live modes only. A provider claims CONTAINER or GVISOR only after passing the live cases; replay alone proves no isolation. Under GVISOR the live cases also run with syscall tracing to catch incompatibilities (ADR 0006). Column "Profiles": a provider runs each case under every profile it offers from that list; "isolated" means CONTAINER and GVISOR.

Every case creates a fresh sandbox with fresh `change_id`, `work_unit_id` and `run_id` values (prefix plus 32 lowercase hex characters), empty host directories under the provider's work root, each named by the `run_id`, the kit's pinned test image and a valid spec, unless a case says otherwise, and destroys it with `release_snapshots` at the end. The kit's canary secret is planted on the host, readable by the runner's user only, before every live case. "Rejected" means the status code named and no sandbox, process or snapshot created. "Bounds" means each listed input alone, every other field valid. Golden vector of the tree digest (`testdata/tree-digest/`): the tree of directory `a`, empty file `a.txt`, file `a/b.txt` holding `hi` and LF, empty directory `e`, symlink `l` to `a/b.txt`, owner-executable file `run.sh` holding `#!/bin/sh` and LF, and file `s p` holding `sp` and LF (other files 0644) hashes `lines.txt` to the hex digest in `sha256.txt`; the kit checks a provider's `worktree_digest` of that tree against it.

## Extended

None in 1.0.0.

## Not covered by this kit

- How the canonical event stream of an executor leaves the sandbox (the Unix socket of the runner design), and the canary test that a provider container cannot reach the executor's socket, are owed by the sandbox context and the plugin host kit.
- How a provider's own containers are launched beside the executor's sandbox is the plugin host's.
- The evidence record types of these RPCs are fixed with the sandbox context; no spec tag ships while they are missing.
- That a provider which cannot freeze refuses Snapshot with FAILED_PRECONDITION: a conforming provider can freeze, so no kit host exercises it; reviewed in the provider's code.
- PROCESS isolates neither the network nor the host filesystem beyond the run's user; its authority ceiling (ADR 0033) is checked by the policy decision point, and HOST-001 pins the host attestation it needs.
